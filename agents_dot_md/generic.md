## Keeping this file honest

This file is the source of truth for repo rules. If any request or change conflicts with something
stated here (e.g. a rule the user wants changed or a constraint that no longer holds):

1. **Flag the conflict to the user explicitly** before acting on it — quote the rule in this file
   and describe what the change would break or override.
2. **Do not silently work around or contradict a documented rule**, and do not edit this file on
   your own initiative.
3. **Update this file only after the user approves** — the user's approval is what makes the new
   rule official. When updating, change only the affected rule(s), not the whole file, and keep
   the same concise style.

If you are unsure whether something is a rule or a stale claim, verify against the code and ask
before proceeding.
